# 赛博禅寺 · Cyber Temple

> 敲 64 拍木鱼，出一张谁都改不了、谁都能重算的禅印。

线上：<https://cyberbuddha.ai>

无账号、无后端、无数据库。整座寺是一个 Vue 3 + Three.js 的静态站点，跑在 Cloudflare 上。

## 玩法

1. **跟拍**：每炷香 64 拍，分 8 句，句首重拍、句末换气。点轨道、点「敲」或按空格，合拍才有权重
2. **出印**：每炷结算生成一张禅印回执，里面写死「第几炷 + 当日种子 + 每一拍的判定」+ 校验码
3. **复算**：任何人都能拿这条回执，用同一个种子重建节拍表，重新跑一遍结算核对结论
4. **战帖**：把回执变成一条链接发给别人 —— 他点开就是同一张 64 拍，敲完立刻比合拍率
5. **共修**：万佛墙上挂愿、替别人诵、按击数分悬赏；「谁在寺里」来自公共公告板
6. **法会**：每天 06:00 / 12:00 / 21:00（各自本地时钟）各十二分钟，修行功德 ×2

## 为什么这么设计

- **没有服务器** → 就没有后台能偷偷给你加功德、也没有人能把你的账本改掉
- **节拍表由公开信标种子生成** → 同一炷是同一道题，所以「战帖」不需要房间与配对
- **规则写在前端源码里** → 寺规面板里的每一条都能在代码里找到对应实现
- **每日增发有额度** → 记账的是稀缺，不是数字

## 诚实边界

- 这是实验原型：无合约、无钱包、无预挖，**不承诺任何收益，可能归零**
- 禅印证明的是「按这套规则该得多少功德」，不证明「是真人真敲」
- 共修与榜上的数字由本人签名自报，点开回执可以自行复算
- 公共公告板用的是免费中继，高频访问会限流，极端情况下退化为只读

## 本地跑

```bash
npm install
npm run dev     # http://localhost:5173
npm test        # node --test，纯函数层全覆盖
npm run build
```

零运行时依赖（除 Vue 与 Three.js）。规则、协议、账本、分享卡全部是可单测的纯函数。
